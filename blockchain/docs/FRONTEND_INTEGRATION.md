# BlockPoll Frontend Integration Guide

This document is for integrating the future **Google Stitch** React UI with the **BlockPoll** smart contract.

---

## 1. Deployment Flow & Contract Address

To deploy the contract to your persistent local blockchain:

1. **Terminal 1**: Start the local Hardhat node
   ```bash
   npx hardhat node
   ```
2. **Terminal 2**: Deploy the contract to the local node
   ```bash
   npm run deploy:localhost
   ```
3. **Copy the printed address**:
   The deployment output will print the actual deployed address:
   ```text
   Actual Contract Address: 0x...
   ```

> [!IMPORTANT]
> Copy the actual address printed in Terminal 2 and paste it into your frontend configuration. Do **not** rely on hardcoded or assumed addresses, as the address is generated at deployment time.

---

## 2. Obtaining the Contract ABI

Hardhat generates the ABI after compiling the Solidity contract. You can find the full artifact at:
```text
blockchain/artifacts/contracts/BlockPoll.sol/BlockPoll.json
```

In your future frontend code, you can either:
- Copy the `abi` array from `BlockPoll.json` into your UI configuration, or
- Directly import the JSON artifact if using a module bundler.

## 3. Election State Enum Reference

The contract function `state()` returns a `uint8` representing the election lifecycle:

| Value | State Name | Description |
| :---: | :--- | :--- |
| **`0`** | `NotStarted` | Initial phase. Candidate and voter registration are open. Voting is disabled. |
| **`1`** | `Ongoing` | Voting is active. Registrations are locked. Registered voters can vote once. |
| **`2`** | `Ended` | Election is closed. No further votes can be cast. Final tallies are immutable and viewable. |

---

## 4. Contract Functions Required by UI

### Read / Public View Functions (No gas cost, callable by anyone)
- **`electionName() -> string`**: Title of the election.
- **`admin() -> address`**: Address of the admin who deployed the contract. Use this to toggle admin UI controls.
- **`state() -> uint8`**: Returns `0` (`NotStarted`), `1` (`Ongoing`), or `2` (`Ended`).
- **`candidateCount() -> uint256`**: Total number of registered candidates.
- **`candidates(uint256 id) -> (uint256 id, string name, uint256 voteCount)`**: Fetches a single candidate. *(Note: IDs start at 1)*.
- **`getAllCandidates() -> Candidate[]`**: Returns an array of all candidate structs (`id`, `name`, `voteCount`).
- **`getVoterStatus(address voterAddress) -> (bool isRegistered, bool hasVoted, uint256 votedCandidateId)`**: Checks if the connected wallet is registered, whether it has voted, and for whom.
- **`getRegisteredVotersCount() -> uint256`**: Returns the total number of registered voters.

### Admin Functions (Transactions sent by `admin` account)
- **`registerCandidate(string name)`**:
  - Allowed only when `state == 0` (`NotStarted`).
  - Rejects empty strings.
  - Candidate IDs start at 1.
- **`registerVoter(address voterAddress)`**:
  - Allowed only when `state == 0` (`NotStarted`).
  - Rejects `0x0` address and duplicate registrations.
- **`startElection()`**:
  - Allowed only when `state == 0` (`NotStarted`).
  - Requires at least 2 candidates registered.
  - Transitions `state` to `1` (`Ongoing`).
- **`endElection()`**:
  - Allowed only when `state == 1` (`Ongoing`).
  - Transitions `state` to `2` (`Ended`).

### Voter Action (Transaction sent by registered voter)
- **`vote(uint256 candidateId)`**:
  - Allowed only when `state == 1` (`Ongoing`).
  - Caller wallet must be registered (`voters[msg.sender].isRegistered == true`).
  - Caller must not have already voted (`voters[msg.sender].hasVoted == false`).
  - Candidate ID must be between `1` and `candidateCount`.

## 5. Contract Events for Real-Time UI Reactivity

Your UI can subscribe to these events for live updates:
- **`CandidateRegistered(uint256 indexed candidateId, string name)`**
- **`VoterRegistered(address indexed voterAddress)`**
- **`ElectionStarted()`**
- **`ElectionEnded()`**
- **`VoteCasted(address indexed voter, uint256 indexed candidateId)`**

## 7. MetaMask Setup & Local Accounts

> [!CAUTION]
> **LOCAL DEVELOPMENT ONLY:**
> The private keys generated by Hardhat are publicly known test keys. They must **NEVER** be used on Ethereum Mainnet, any public testnet, or with real cryptocurrency funds. Use them strictly inside your local private sandbox.

To interact with the local blockchain in your browser:
1. Open MetaMask -> **Add a network manually**.
   - Network Name: `Hardhat Localhost`
   - New RPC URL: `http://127.0.0.1:8545`
   - Chain ID: `31337`
   - Currency Symbol: `ETH`
2. Import a local development test account:
   - When you start `npx hardhat node`, Hardhat lists 20 local test accounts with their private keys.
   - Import Account #0 into MetaMask to test as the **Admin**.
   - Import Account #1 and Account #2 to test as **Voters**.
